# 학교 축제 NFC 태그 관리 시스템

학교 축제 부스 방문을 NFC 태그로 인증하고, 학생별·부스별 방문 기록을 관리하기 위한 팀 프로젝트입니다.

> **현재 단계:** 프로젝트 초기 세팅  
> **기술 스택:** 미확정 — 팀 논의와 NFC 기기 테스트 후 결정합니다.

## 프로젝트 목표

- 학생 한 명당 NFC 카드 또는 스티커 한 개를 배부합니다.
- 부스 담당자는 스마트폰으로 학생 태그를 확인하고 방문을 기록합니다.
- 관리자는 학생별·부스별 방문 현황을 조회할 수 있습니다.
- 축제 현장에서 빠르고 안정적으로 운영할 수 있는 시스템을 만듭니다.

## 예상 운영 규모

- 부스: 약 10~20개
- 인증 수단: 학생별 NFC 카드 또는 스티커 1개
- 담당자 기기: Android 및 iPhone 혼재 가능

## 운영 흐름(초안)

1. 관리자가 학생과 부스 정보를 등록합니다.
2. 학생에게 개인 식별용 NFC 태그를 배부합니다.
3. 부스 담당자가 인증 화면을 열고 학생 태그를 확인합니다.
4. 서버가 인증 요청을 검증하고 방문 기록을 저장합니다.
5. 관리자가 대시보드에서 방문 현황을 확인합니다.

## 꼭 확인할 기술적 제약

- Web NFC는 기기·브라우저 지원 범위가 제한적이며, 일반적인 iPhone Safari에서는 사용할 수 없습니다.
- Web NFC로 태그의 고유 UID를 읽을 수 있다고 가정하지 않습니다. 태그에는 개인정보 대신 무작위 식별 토큰을 사용하는 방식을 우선 검토합니다.
- HTTPS, 지원 브라우저, 화면 활성 상태 등 실제 운영 조건을 기기별로 검증해야 합니다.
- iPhone 담당 부스를 위한 대체 인증 방식 또는 Android 예비 기기 운영안을 마련해야 합니다.
- 중복 태깅, 네트워크 장애, 오프라인 상황에 대한 대응을 설계해야 합니다.

## 팀원이 시작하는 순서

1. 저장소를 Clone 하거나 GitHub에서 초대를 수락합니다.

3. 팀 회의에서 기술 스택, 인증 방식, 역할 분담을 확정합니다.
4. 담당 기능은 기능 명세서 양식에, API는 API 명세서 양식에 기록합니다.
5. 작업 전 [기여 방법](CONTRIBUTING.md)을 확인합니다.

## 보안 원칙

- 태그에 이름, 학번, 전화번호 등 개인정보를 직접 저장하지 않습니다.
- 인증 토큰은 추측하기 어려운 무작위 값으로 설계합니다.
- 관리자 비밀키, API 키, 비밀번호, 실제 학생 개인정보를 GitHub에 올리지 않습니다.
- 인증 및 방문 기록 검증은 서버 측에서도 수행합니다.
