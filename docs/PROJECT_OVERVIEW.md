# 프로젝트 개요 및 결정 사항

## 1. 프로젝트 목적

학교 축제에서 학생의 부스 방문을 NFC 태그로 인증하고, 방문 이력을 일관된 방식으로 관리합니다.

## 2. 사용자 및 역할(초안)

| 사용자 | 주요 작업 |
|---|---|
| 학생 | 개인 NFC 태그 제시 |
| 부스 담당자 | 학생 태그 인증 및 방문 기록 확인 |
| 관리자(학생회) | 학생·부스 관리, 방문 현황 및 통계 조회 |

권한과 세부 기능은 기능 명세 회의에서 확정합니다.

## 3. 운영 조건

| 항목 | 현재 내용 | 상태 |
|---|---|---|
| 학생 태그 | 학생 1명당 카드 또는 스티커 1개 | 논의된 방향 |
| 부스 수 | 약 10~20개 | 예상 |
| 담당자 기기 | Android/iPhone 혼재 가능 | 확인 필요 |
| 인증 방식 | NFC 기반 | 목표 |
| 기술 스택 | 미정 | 결정 필요 |
| 배포 환경 | 미정 | 결정 필요 |

## 4. 기본 운영 흐름

1. 관리자가 학생 및 부스 데이터를 준비합니다.
2. 학생별 무작위 식별 토큰을 생성해 태그에 기록하는 방식을 검토합니다.
3. 부스 담당자가 인증 화면에서 태그를 스캔합니다.
4. 서버가 토큰, 권한, 중복 방문 정책 등을 검증합니다.
5. 방문 성공 또는 실패 결과를 담당자에게 보여줍니다.
6. 관리자는 실시간 또는 갱신된 방문 통계를 조회합니다.

## 5. 기술 검증이 필요한 위험 요소

### NFC 및 기기 호환성
- Web NFC는 지원 브라우저와 기기가 제한됩니다.
- iOS Safari에서 일반적인 Web NFC를 사용할 수 있다고 전제하지 않습니다.
- 태그 UID를 웹에서 읽는 방식으로 설계하지 않습니다.
- 실제 사용할 Android/iPhone 기기와 태그를 확보해 사전 테스트합니다.

### 네트워크 및 중복 요청
- 통신이 끊겼을 때 재시도 또는 대체 인증 절차가 필요합니다.
- 같은 학생이 같은 부스에서 연속 태깅했을 때의 처리 정책을 정합니다.
- 서버에서 중복 기록 방지와 요청 검증을 수행합니다.

### 개인정보 및 보안
- NFC 태그에는 개인정보를 직접 저장하지 않습니다.
- 무작위 토큰과 실제 학생 정보의 연결은 서버에서 관리합니다.
- 최소한의 개인정보만 수집하고 접근 권한을 구분합니다.
